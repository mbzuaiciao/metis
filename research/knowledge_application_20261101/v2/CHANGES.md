## Dataset corrections

- **eval-01–20:** replaced all generic knowledge prompts and label-like keys with instrument-specific theoretical questions and explanatory financial relationships. Added a general `knowledge_boundary` separate from the application boundary. No case numbers, supplied application facts, labels or answers enter knowledge prompts. Theoretical principles necessarily overlap with the application construct; this is an intended probe, not evidence of hidden knowledge.
- **eval-01:** floating-rate callable debt and an unspecified signed swap contract; interest-only, floating-index-independence target on every permitted call path. Request actual signed schedules/notionals/index/call-linked terms. Removed the wrong implication that a selected call policy proves an all-path target. A known violating path would permit a direct negative conclusion, but these facts do not specify one.
- **eval-05:** knowledge probe explicitly identifies a knock-out put and pathwise floor; application target requires barrier/monitoring and post-knock-out net cash flows without asserting a realized breach.
- **eval-09:** asks about cash available for a EUR call, not collateral already posted; eligibility/haircuts and timely direct USD posting or net EUR conversion/transfer govern the answer; both alternative routes need not be executed.
- **eval-10:** theoretical question explicitly includes senior priority and existing-reserve top-up; knowledge key derives max(required minus existing reserve,0), without application values.
- **eval-17:** asks for sector-level linked annual contributions under the report's method. Supplies both sectors' monthly arithmetic effects for all twelve months; portfolio/benchmark return paths and linking convention remain necessary. Defines annual active return as the difference between the two compounded returns, and acknowledges special coincidences in raw addition.
- **eval-19:** explicitly asks for annualized money-weighted IRR, distinguishes it from a liquidation multiple, and requires the zero-NPV relationship and dated cash flows. Generic root-multiplicity discussion is no longer mandatory; actual ambiguity remains reportable.
- **eval-15:** asks actual offshore USD service capacity; missing key includes dated bond/prior obligations as well as usable timely transferable resources.
- **train-16/20/33/50:** ask overall noon funding, legally due gated Friday payouts, actual PD change, and quantified time-weighted return respectively. Scope now matches the unresolved inputs; TWR additionally needs valuations around flows.
- **train-13/26/35:** removed assumed positive futures P&L; added physical/crack-spread coverage; specified certified drawable borrowing base and guarantee collectibility/guarantor capacity in the same default state.
- **train-15/41/43/52:** clarified realized roll proceeds, quantified EAD, joint-stress net counterparty exposure, and matched unsmoothed monthly volatility. These avoid equating lack of proof of a broad guarantee with inability to answer an already determined narrow question.
- **All 30 insufficient training cases and all 10 insufficient held-outs:** removed overt absent/unknown/not-supplied lists from evidence. Targets state the actual uncertainty and its financial consequence. eval-04 loses its meta statement that the test is complete. All 80 user prompts use the same neutral scope/uncertainty wrapper. Economically necessary contractual and no-other-source assumptions remain; cues are reduced, not eliminated.

A [case-by-case financial audit](CASE_REVIEW.md) records all 80 cases, including revised prompts/keys and retained arithmetic. This is author review without model calls, not human adjudication or a reliability estimate.

## Scoring and execution

- Knowledge packets contain only theoretical question/response and `knowledge_required`/`knowledge_boundary`. Application packets contain no knowledge key. Separate 60-row blank sheets support staged release. Combined 120-row packet/sheet and identity key remain custodian-only. Knowledge ratings must be locked before any application material or rubric is released.
- Non-EOS output or an empty generated-token sequence is saved, then evaluation raises `TruncatedResponse`, exits nonzero and retains `status=incomplete`. `completed` counts EOS outputs; `saved`, `truncated`, `attempted`, `unavailable`, last task, failure class and saved-record hashes are separate. A generation exception also stops collection. Fatal process termination may leave a started/stale manifest; that is incomplete for the training gate.
- Training requires `--baseline-runs A_RUN B_RUN`. Before model imports/output creation, the gate checks both complete 40-slot arms, freeze/config, record identities/messages/status, content hashes and shared snapshot/template. Training also checks its snapshot/template match. This is provenance/integrity checking, not authentication against deliberate artifact fabrication. No response content is exposed for human inspection by the gate.
- Offline tests use synthetic callbacks/records only to exercise stopping, nonzero process exit, missing/corrupt/truncated baseline rejection, default plans, prompt controls, staged-key separation and human-score arithmetic. These fixtures are not model outputs or human ratings.
